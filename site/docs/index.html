Install yapp

You need tmux and curl. The installer uses Python 3.11+ if available, or downloads a private Python 3.13 when your system has only Python 3.10 or no Python. Use a terminal at least 80 columns by 18 rows. Install and authenticate the coding CLI you want to use separately.

Check your prerequisites

python3 --version
tmux -V
curl --version

On Ubuntu or Debian:

sudo apt-get update
sudo apt-get install python3 python3-venv python3-pip tmux curl git

For pipx or source installs, confirm Python is 3.11 or newer. The recommended installer handles older or missing system Python automatically. On macOS, with Homebrew installed, use brew install python tmux git; macOS includes curl. On Windows, run the Linux instructions inside WSL2.

Run the installer

Linux · macOS · WSL2
curl -fsSL https://yapp.riggedcode.com/install.sh | sh

Inspect the script before running it if you prefer. It installs the latest published release, or main when no release is available, into a private virtual environment. It creates yapp and goon commands in ~/.local/bin. Any downloaded Python and uv tool stay under the yapp install directory; system Python and shell profiles are unchanged.

yapp --help
goon --help

These help commands do not start the server or agents. If your shell cannot find them, follow the installer's PATH instructions and open a new terminal.

Prefer pipx or a source checkout?

With pipx and Git already installed, run:

pipx install git+https://github.com/Ankitkkkk/yapp.git

For editable installs, manual server startup, or detailed platform notes, use the full installation checklist. Older release ZIP bundles built by build_release.py do not include the complete TUI.

Create your first session

  1. Run yapp in your terminal. Without an explicit server URL, it can start the local server in tmux.
  2. Create a session. Name it, then select an orchestrator provider and an absolute project directory such as /home/you/projects/app. Submitting starts the provider CLI you selected.
  3. Add a worker. Press F3, choose Add agent, and set its provider, name, and project directory. For example, choose Codex and name it reviewer.
  4. Send a task. Enter INSERT mode with i, type @reviewer review the latest changes, then press Escape followed by Enter to send. Unaddressed requests go to the enabled orchestrator.
  5. Handle provider prompts. Press F6, choose the agent, and accept any trust or approval prompt in its own terminal.

In input forms, use ↑/↓ to move between fields and buttons. Tab/Shift+Tab cycles provider and other choices within a field. Working directories suggest matching folders as you type; Tab selects a suggestion and Enter accepts it. Press Enter again to submit, or use the arrows to continue editing.

Keep the agent running when you return. From an attached terminal outside tmux, press Ctrl+B, then D to detach. Inside tmux, use tmux switch-client -l to return to the previous session. Ctrl+C may stop the provider.

Waiting indicators are advisory. The provider's terminal is the place to inspect and resolve approval prompts.

Commands & controls

Check state without starting agents

With the yapp server already running, these commands read state. Shell commands do not auto-start the server.

yapp status --json
yapp sessions --json
yapp read --session billing --limit 20 --json

Replace billing with an existing session name or ID. --json controls output format; it does not make a command read-only. Interactive chat and attach do not support JSON output.

Create a session from a script

The following commands create a session, start a real provider, and send it a message. Replace the project path with your own absolute directory.

yapp new billing --json
yapp spawn codex --session billing \
  --cwd /absolute/project --agent-name reviewer
yapp send --session billing "@reviewer review the latest changes"

A plain yapp new creates the session without an orchestrator. To start one, use yapp new billing --orchestrator-provider claude --cwd /absolute/project --json instead of the first command.

Read Markdown and copy its source

The TUI renders headings, emphasis, lists, blockquotes, links, tables, and syntax-highlighted code in conversation, Activity, Help, agent details, and notices. On narrow terminals, tables stack their values. Compare formatted and raw text in the homepage demo.

  1. Press F7 to show original Markdown and pause message editing.
  2. Select text using your terminal, then use its Copy shortcut, such as Ctrl+Shift+C in GNOME Terminal. Backticks and code indentation remain in the source.
  3. Press F7 again to restore formatting, scroll position, and your draft.

F7 releases the app's mouse capture. Inside tmux, you may still need Shift-drag or tmux copy mode. Browser chat has a per-message raw Markdown copy button.

After upgrading, close and reopen the TUI to load the renderer. Source checkouts need the updated terminal dependencies: .venv/bin/python -m pip install -r requirements-cli.txt.

Provider support

yapp connects existing tools; it does not install provider CLIs, log in for you, or include their subscriptions.

  • Terminal agents: Claude Code, Codex, Gemini CLI, GitHub Copilot CLI, Antigravity, Kimi, Qwen Code, Kilo CLI, and CodeBuddy are configured CLI providers.
  • Conversation resume: built-in native-session adapters are provided for Claude and Codex. Other CLI providers can start fresh; restoring a native conversation requires an adapter that supports it.
  • API agents: MiniMax and OpenAI-compatible servers such as Ollama or LM Studio use wrapper_api.py with separate configuration. They are not the same as tmux agents added through the terminal session picker.

See the API-agent setup and local configuration example. Add local agents under a new, unused name; local configuration does not replace existing provider definitions.

Local chat, provider-dependent processing. yapp stores chat and sessions locally and listens on localhost by default. Cloud agents still send prompts and context to their providers. Provider fees and data policies apply separately.

Updates & data

Run yapp --version to show your installed version without starting the server.

Package installs check for published releases every six hours while the TUI is open. Automatic installs are enabled by default. To check or update manually:

yapp update --check
yapp update

Set YAPP_NO_AUTO_UPDATE=1 to disable automatic installation, or YAPP_NO_UPDATE_CHECK=1 to disable checks. You can also set auto = false or check = false under [updates] in config.local.toml.

Source checkouts are not automatically updated. Inspect local changes before pulling, update dependencies, and restart affected processes after accounting for active work.

Install changes from your local checkout

To copy a checkout's current code, including unpublished changes, into the installer's existing environment, run this from the repository root:

YAPP_SOURCE="$PWD" sh install.sh

Then close and reopen yapp. Use Restart server for server changes. yapp update follows published releases; it does not install uncommitted local edits.

Package state lives under ~/.local/share/yapp/ by default (or $XDG_DATA_HOME/yapp). Source checkouts use data/ and uploads/. Preserve those directories and your private configuration when upgrading.

Troubleshooting

“Externally managed environment”

Use the installer or pipx, which isolate Python dependencies. Do not replace pipx with system pip or use --break-system-packages.

Python is too old or missing

Rerun the current installer; it downloads a private compatible runtime automatically. If you explicitly set PYTHON, point it to a Python 3.11+ executable or unset it to allow automatic selection. Check network access to Astral and GitHub if a runtime download fails.

Server connection failed

Open yapp in a terminal to auto-start the local server. From a source checkout, run .venv/bin/python run.py manually. The default web/API address is http://127.0.0.1:8300; MCP uses http://127.0.0.1:8200/mcp. Shell status checks alone do not start it.

An agent looks stuck

Check that its CLI is installed and authenticated and its project directory exists. Use F5 for Activity and F6 to inspect its terminal for trust or approval prompts. An orchestrator needs to be running, ready, and enabled before it can route work.

Copy or function keys behave differently

Some keyboards need Fn with function keys. Use F7 to release mouse capture before selecting text. Inside tmux, Shift-drag or tmux copy mode may be needed. Copy behavior depends on your terminal.

For more cases, use the installation troubleshooting checklist. Include your OS, Python version, and command when reporting a problem; remove tokens and private chat data from logs.
