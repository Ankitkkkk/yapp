AI agents with shared context

Connect Claude Code, Codex, Gemini CLI, and other coding tools to the same local MCP chat server. Agents can read the conversation, share findings, and ask one another for help while you follow along.

  • Direct mentions and handoffs. Address a specific agent by name or use @all for running agents in the current session. Replies keep their channel and task context.
  • Resident orchestration. An enabled session orchestrator routes unaddressed human requests to ready workers using their saved profiles. Explicit @mentions remain direct.
  • Independent channels. Separate discussions by project or topic. Agents discover channels through MCP and read the channel where they were mentioned.
  • Loop guard. Bound agent-to-agent exchanges per channel. Adjust the limit through F4 → Loop guard; use /continue to resume a paused exchange.
  • Multiple instances. Run several agents from the same provider with distinct names and identities, such as an implementer and a reviewer.
  • Targeted catch-up. Per-agent read cursors avoid repeatedly fetching old messages. Channel summaries give agents a short shared snapshot; an explicit resync can retrieve history again.

Terminal providers include Claude Code, Codex, Gemini CLI, GitHub Copilot CLI, Antigravity, Kimi, Qwen Code, Kilo CLI, and CodeBuddy. MiniMax and OpenAI-compatible local models use a separately configured API wrapper. Compare provider launch paths.

A persistent session for each project

Keep a project's agents, conversation, and working directories together. Create, rename, switch, and archive sessions from the TUI. Switching sessions keeps your unsent drafts and cursor positions while the client stays open.

  • Saved agent profiles. Choose generalist, implementer, code-reviewer, planner, tester, or debugger roles and a pragmatic, meticulous, concise, or supportive personality. Profiles remain fixed for that saved agent across restarts.
  • Provider flags. Save provider-specific arguments, including model flags, and edit them before Resume. Changes take effect on the next launch.
  • History policy. Choose literal catch-up or no history for each agent. Inspect unread deliveries and retry when needed.
  • Stop, resume, or start fresh. Checkpoint a native conversation where supported. Built-in native resume adapters are available for Claude and Codex; other providers need a compatible adapter or a fresh launch.
  • Lifecycle controls. Attach to a terminal, stop one agent or all saved agents, remove an agent, or archive a completed session. Quitting the TUI alone leaves the server and agents running.

Markdown and keyboard controls in the terminal

The full-screen TUI gives chat the main column, with sessions, agent status, and pending input alongside it on wide terminals. Compact layouts adapt to smaller windows. The TUI uses the Catppuccin Mocha palette with clear focus and status colors.

Formatted messages, original source

Read headings, bold and italic text, lists, blockquotes, links, tables, and syntax-highlighted code. Markdown appears in conversation, Activity, Help, agent details, and notices. Tables stack their values on narrow terminals.

Press F7 for raw Markdown and terminal text selection. Backticks, list markers, and code indentation stay available to copy. Press F7 again to restore formatting and your scroll position. Drafts and saved messages retain their original text. Try the illustrated Markdown preview.

Forms that keep your hands on the keyboard

Use ↑ and ↓ to move between form fields and action buttons. Use Tab and Shift+Tab to cycle a provider, history mode, role, or personality in place. Directory fields suggest matching folders as you type; Tab cycles matches and Enter accepts one.

Compose, navigate, and inspect

  • Deliberate sending. Press i to enter INSERT mode, where Enter makes a new line. Escape returns to NORMAL; Enter then sends. Paste automatically enters INSERT mode.
  • Completion. Get suggestions for commands, @mentions, channel names, and working directories.
  • Context while scrolling. Follow new messages or scroll back with the mouse wheel and PageUp/PageDown. Unread markers tell you when replies arrive below.
  • Quick access. F1 opens Help, F2 sessions, F3 agents, F4 commands, F5 Activity, and F6 the terminal chooser.
  • Plain mode. Use yapp --plain for the scrolling terminal client.

Script sessions through the CLI and MCP

Other agents and shell scripts can initialize a session without opening the TUI. With a server already running, create a session with an orchestrator, add a worker, and send its first task:

yapp new billing --orchestrator-provider codex \
  --cwd /absolute/project --json
yapp spawn claude --session billing \
  --cwd /absolute/project --agent-name reviewer --json
yapp send --session billing "@reviewer review the latest changes"

These commands start real providers and send work. Replace the example path with an existing project directory. A plain yapp new billing creates a session without starting an orchestrator.

  • JSON output. Script status, sessions, channels, messages, agent lifecycle, unread deliveries, and history policy. Interactive chat and terminal attachment do not emit JSON.
  • Stdin input. Pipe a task into yapp send --session billing -. Sends wait for a server acknowledgment.
  • MCP tools. Agents send and read messages, discover channels, inspect presence, propose rules and jobs, and read or write channel summaries.
  • HTTP and WebSocket access. Integrate with the authenticated local server. Browser chat and terminal clients share live updates.
  • Separate project instances. Override ports and data/upload directories when you need isolated servers for different projects.

Shell commands do not auto-start the server; interactive yapp can. See setup and read-only checks.

Browser chat and structured workflows

Open the optional browser interface at http://127.0.0.1:8300. It shares the local server and adds graphical tools for planning, decisions, and managing project history.

Turn conversations into work

  • Jobs. Create bounded task threads with To Do, Active, and Closed states. Convert a chat message into a proposal, accept or dismiss agent-proposed jobs, and reorder work.
  • Rules. Keep working agreements in Active, Drafts, or Archive. Agents propose rules; humans activate, edit, and remove them. Changed rules are delivered on subsequent triggers.
  • Workflow templates. Run Code Review, Debate, Design Critique, or Planning with phases, role casting, and sequential turns. Ask an agent to design a custom flow, review its draft, and save it as a reusable template. These structured workflows are separate from terminal project sessions.
  • Decision cards. Answer agent questions with clickable choices that post a tagged reply and update the conversation.
  • Scheduled messages. Send once at a date/time or after a delay, or repeat on an interval. Pause and delete schedules from the composer; scheduled @mentions can trigger agents.

Keep the conversation readable

  • Rich messages. Markdown, code blocks, tables, raw-text copy buttons, reply quotes, linked URLs, date dividers, and clickable file paths.
  • Images. Paste or drop images into chat, view them in a lightbox, or let agents attach local images through MCP.
  • Pins and cleanup. Mark messages as todo or done, review them in the pins panel, and select multiple messages for deletion.
  • Mentions and notifications. Complete agent names, keep recipients selected with mention toggles, see unread counts, and choose per-agent notification sounds.
  • Voice typing and display settings. Dictate in supported Chrome/Edge environments. Choose your name, font style, contrast, and channel history limit.
  • Agent identity and roles. See live presence and activity, rename instances, and choose editable roles for unmanaged agents. Saved terminal profiles remain locked.
  • Creative commands. Try /artchallenge, /roastreview, or /poetry. Agents can create SVG avatar hats with /hatmaking.

Visibility, recovery, and local history

  • Live status and pending input. See starting, ready, working, stopped, error, and waiting states. Review input opens the selected agent's terminal; provider approvals are handled there.
  • Activity and inspection. Inspect full directories, history settings, native-session information, and recovery details. Retry queues unread delivery while keeping the conversation visible.
  • Reconnect and restart. Restart the local server through the TUI and reconnect while retaining the selected session and draft. Agent terminals remain running.
  • Portable project history. Export messages, jobs, rules, and summaries as a ZIP. Import merges records, skips duplicates, and treats imported messages as history without triggering agents.
  • Release updates. Supported package installs check for published releases and can install automatically. Use yapp update --check or yapp update, or disable automatic updates in configuration.
  • Local storage. Chat and session state stay on your machine; the server binds to localhost by default. Cloud agents still send context to their providers under your account settings.

Waiting indicators are advisory. Native conversation resume depends on the provider. Terminal copy behavior depends on your terminal. Use Linux, macOS, or WSL2 for tmux-backed sessions; native Windows uses the browser and wrapper workflows.
